# Project Overview

**ALSense — From the first symptom to the next breakthrough.**

ALSense is planned as an accessibility-first system for symptom documentation, longitudinal monitoring, physician-ready summaries, and optional, separately consented research contribution. The first release must frame early recognition as documentation and referral support—not diagnosis—and progression estimates as research outputs with model/version provenance, uncertainty, and clear limitations.

## Current phase

The repository began empty. This phase establishes a lightweight Python data/ML foundation around real public research data. The BioHacks hacker package was subsequently supplied and reviewed; its fictional case pages are now the sole source for the detailed Alex demonstration profile. No measurements were inferred.

The scientific priority is prospective validity: a feature is eligible only if it would have been available at a declared prediction time. The packaged CASIdata table does not provide visit-level timestamps sufficient to prove that its longitudinal summaries meet this condition, so the initial baseline excludes all of them.

## Non-goals

- No ALS diagnosis, exclusion, risk percentage, or medical-device claim.
- No polished UI or automated treatment/referral decision.
- No Gemini, Tiger Data, Solana, ElevenLabs, or Vultr implementation yet.
- No patient uploads, real health information, deployment, or on-chain health data.
